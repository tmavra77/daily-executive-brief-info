Data practices

Privacy notice

Last updated: 19 October 2026

Daily Executive Brief is a personal automation operated by tmavra77. It processes the owner's task and calendar data to send a briefing to the owner's fixed Gmail address. It is not offered as a public account-based service.

Information accessed

  • Google Calendar: event records from the primary calendar, including titles, dates, times, all-day status, locations and event status. Invitation response information is used to exclude events the owner has declined.
  • Gmail: send permission to deliver the generated brief from the authorized account. The utility does not request permission to read the mailbox.
  • Notion: task titles, statuses, action dates, priorities and types from the single configured task data source, using a read-only connection.
  • Credentials: the Google OAuth client configuration and refresh token, and the Notion connection token and source identifier.

Purpose and processing

Information is used to select and organize scheduled tasks and calendar commitments, generate the brief, and deliver it to the owner. The summary uses deterministic rules. Google user data is not sold, used for advertising, supplied to an AI service, or used to train models.

Google API data is used only to provide the personal briefing features described here, in accordance with the Google API Services User Data Policy, including its Limited Use requirements.

Where information is processed and stored

Scheduled runs process data on GitHub Actions runners. Local runs process data on the owner's computer. Google supplies calendar data and delivers and stores email through Gmail; Notion supplies task data.

Credentials are stored in ignored local configuration files and GitHub repository secrets. Temporary Google access tokens are held in memory. The supplied workflows do not publish task or event content in their logs or upload briefing content as artifacts.

Dry runs write briefing preview files on the computer or runner where they execute. Local previews remain until the owner removes them. On this installation, the local project is in a Google Drive folder, so local files may also be synchronized by Google Drive according to the owner's settings.

Briefing emails remain in Gmail until removed under the account's retention settings. Date-based delivery markers are stored locally and, for scheduled runs, in the repository's GitHub Actions cache. These markers record delivery state and do not contain task or event content. GitHub controls runner cleanup and cache retention.

Sharing

Briefs are addressed only to the owner's configured Gmail address. Data is processed by the providers needed to run the utility: Google, Notion and GitHub, under the owner's account settings and those providers' policies. There is no public task or calendar feed.

Controls, deletion and revocation

The owner can stop future runs by disabling the GitHub Actions workflow, revoke Google authorization through Google Account settings, and remove the Notion connection's database access in Notion. Existing emails and local previews can be deleted with the corresponding Gmail or filesystem controls. Revoking authorization does not itself delete previously created copies.

This information website

These static pages do not request Google authorization, collect task or calendar data, or include application analytics or advertising. If hosted on GitHub Pages, GitHub processes website requests and logs visitors' IP addresses for security purposes, as described in its privacy statement.

Contact

The owner is identified by the tmavra77 GitHub profile. The support email configured for the OAuth application is available through Google's consent interface.
